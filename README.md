# Мессенджер в стиле Telegram

Внешний вид и поведение приближены к Telegram: список чатов слева с превью
последнего сообщения, переписка — классическими пузырями (свои сообщения
справа, зелёно-белые, чужие — слева, белые), поиск по чатам, статус
"печатает…" в шапке, галочки прочтения.

## Как запустить в VS Code

1. Установи Node.js: https://nodejs.org (LTS)
2. Открой папку `chat-app-tg` в VS Code
3. В терминале (Ctrl + `):
   ```bash
   npm install
   npm start
   ```
4. Открой в браузере: `http://localhost:3000`

## Проверить с "двумя аккаунтами"

Открой обычную вкладку и приватное окно браузера, зайди под разными именами —
сообщения будут приходить друг другу мгновенно.

## Что реализовано

- Список чатов с аватарами, превью последнего сообщения и временем
- Поиск по чатам (фильтрация в реальном времени)
- Пузыри сообщений: свои — справа, чужие — слева
- Группировка сообщений одного автора подряд (аватар только у последнего)
- Галочки "прочитано" на своих сообщениях
- Индикатор "печатает…" в шапке чата (можно отключить в настройках)
- Счётчик непрочитанных сообщений на чатах, которые сейчас не открыты
- Создание новых чатов
- Тёмная/светлая/системная тема, акцентный цвет, фон переписки, размер шрифта
- **Вход по юзернейму и паролю** — отдельные вкладки «Вход» / «Регистрация», пароль хранится только как scrypt-хеш; после нескольких неверных попыток — временная блокировка
- **Уникальный юзернейм (@username), как в Telegram** — это логин аккаунта; сервер не даст занять юзернейм, который уже используется другим аккаунтом
- Смена юзернейма в Настройках → Аккаунт (без создания нового Nova ID)
- Выход из аккаунта (Настройки → Аккаунт → «Выйти из аккаунта»)
- **Бейдж «подтверждён»** у имени пользователя, выдаётся вручную через отдельную админ-консоль `/admin.html` (см. раздел ниже)
- **Код безопасности (verified safety number)** — кнопка 🔐 в шапке личного чата открывает экран сверки: короткий отпечаток связки публичных identity-ключей обеих сторон (как security code в Signal/WhatsApp). Сравнили вслух/лично — отметили галочкой «код сверен».
- **Индикатор смены ключа собеседника** — при первом чате с человеком его ключ запоминается (TOFU). Если сервер потом присылает другой ключ для того же собеседника (переустановил приложение, зашёл с нового браузера — или потенциальный MITM), в чате появляется жёлтый баннер-предупреждение вместо тихой замены ключа; нужно явно сверить код или подтвердить «это точно он».
- **Шифрование стикеров и GIF** в личных чатах — как и текст, они шифруются на клиенте тем же ratchet'ом (сервер видит только шифротекст, а не эмодзи/URL).
- **Сброс шифрования чата** — кнопка ♻️ рядом с 🔐 в шапке личного чата. Нужна на случай, если ratchet-состояние конкретного чата разошлось с собеседником (например, был открыт один аккаунт в двух вкладках/окнах одновременно) и сообщения перестали расшифровываться. Удаляет только локальное ratchet-состояние этого чата на этом устройстве; собеседника трогать не нужно — его клиент подхватит новый бутстрап автоматически при следующем сообщении от тебя (через уже имеющуюся логику восстановления после потери состояния).
- **PIN-блокировка локального хранилища** (Настройки → Аккаунт) — шифрует приватный identity-ключ и ratchet-состояния переписок в IndexedDB AES-GCM ключом, выведенным из PIN (PBKDF2). Без PIN эти данные при включённой блокировке не читаются даже при прямом доступе к профилю браузера. Есть кнопка сброса на случай забытого PIN (обнуляет локальные ключи этого устройства, история на сервере не трогается).

## Как работает вход

Это демо-проект без базы данных, поэтому "телефонные номера" здесь — не
настоящие: **Nova ID** (вида `NOVA-482913`) — это просто внутренний
идентификатор аккаунта, который сервер генерирует при регистрации.

Как это устроено:

1. На экране входа две вкладки: **«Вход»** (юзернейм + пароль) и
   **«Регистрация»** (имя, юзернейм, пароль).
2. При регистрации юзернейм обязателен и должен быть свободен —
   он и есть логин аккаунта. Пароль сохраняется на сервере только как
   **хеш** (scrypt + соль), сам пароль нигде не хранится и не
   логируется.
3. При входе сервер ищет аккаунт по юзернейму и сверяет пароль. Не
   совпал — вход отклоняется, а счётчик неудачных попыток для этого
   юзернейма растёт; после нескольких подряд — временная блокировка.
4. Аккаунт **не привязан к браузеру или устройству** — с юзернеймом и
   паролем можно войти с любого устройства, как в обычном мессенджере.
   Браузер запоминает только сам юзернейм (для автоподстановки в поле
   входа), пароль — никогда.
5. Nova ID и текущее имя видны в Настройках → Аккаунт; там же можно
   переименовать аккаунт или сменить юзернейм (это не создаёт новый
   аккаунт — тот же Nova ID остаётся, юзернейм при этом всегда должен
   быть занят каким-то значением, снять его совсем нельзя).

**Важно:** это по-прежнему демо-проект без базы данных — при
перезапуске сервера все аккаунты и пароли теряются (это просто
in-memory `Map`, не постоянное хранилище). Восстановления пароля пока
нет — забыл пароль, доступ к аккаунту не вернуть. Для полноценной
защиты в продакшене нужны: постоянная база данных, восстановление
пароля, HTTPS/WSS и (если это должно заменять телефонную регистрацию,
как в Telegram) настоящая SMS/email-верификация.

## Админ-консоль (модерация, аккаунты, группы)

Отдельная страница `/admin.html` — консоль разработчика/модератора, не
связанная с обычными аккаунтами: вход по паролю сервера (можно завести
несколько именных админ-аккаунтов — см. ниже).

**Куда класть файлы:** `admin.html`, `admin.js` и `admin.css` — в папку
`public/`, рядом с `index.html`.

**Пароль админки** задаётся переменной окружения `ADMIN_PASSWORD`:

```bash
ADMIN_PASSWORD=мой-секретный-пароль npm start
```

Если переменную не задать, используется пароль по умолчанию `admin123` —
сервер выведет предупреждение в консоль. Для чего-то серьёзнее локального
теста обязательно задай свой пароль.

**Несколько именных админ-аккаунтов** (чтобы в журнале действий было видно
не только IP, но и кто именно это сделал) — переменная `ADMIN_ACCOUNTS`
с JSON-массивом вместо `ADMIN_PASSWORD`:

```bash
ADMIN_ACCOUNTS='[{"name":"Алиса","password":"пароль-алисы"},{"name":"Боб","password":"пароль-боба"}]' npm start
```

Каждый пароль в списке — это отдельный "аккаунт" со своим именем; сама
консоль по-прежнему одна на всех, без ролей и прав — только подпись в
журнале, кто выполнил действие.

Что есть в консоли:

- **Статистика вверху** — всего аккаунтов, сколько сейчас онлайн,
  забанено, сколько групп и сообщений суммарно по всем чатам.
- **Вкладка «Аккаунты»** — список всех зарегистрированных аккаунтов:
  - онлайн/офлайн статус (точка у имени) и дата регистрации;
  - галочка «подтверждён» (как и раньше);
  - галочка **«забанен»** — банит аккаунт: он не сможет войти (ни по
    паролю, ни по сохранённой сессии), а если был в этот момент онлайн —
    все его активные вкладки/устройства тут же разлогинивает с
    объяснением причины. Снять галочку — разбан, вход снова работает.
  - кнопка **⏏ «разлогинить»** — принудительно завершает все текущие
    сессии аккаунта на всех устройствах, но НЕ банит: человек может
    просто войти заново. Полезно, например, если нужно применить смену
    пароля или прогнать подозрительную активную сессию.
  - кнопка **🔑 «сбросить пароль»** — открывает окошко с полем нового
    пароля; сохраняет его как обычный scrypt-хеш, разлогинивает все
    активные сессии этого аккаунта. Единственный способ вернуть доступ,
    если пароль забыт (полноценного самостоятельного восстановления
    пароля в приложении по-прежнему нет — см. раздел выше). Новый
    пароль нужно сообщить человеку отдельно, не через это приложение.
- **Вкладка «Группы»** — список всех групповых чатов (включая общий чат)
  с числом участников, сообщений, владельцем и датой создания. Для
  любой группы, кроме общего чата, есть кнопка удаления — сносит группу
  целиком, вместе с историей, у всех участников сразу.
- **Вкладка «Заблокированные входы»** — юзернеймы, которые сейчас не
  могут войти из-за временной блокировки после нескольких неверных
  попыток пароля (антибрутфорс), с кнопкой снять блокировку вручную —
  на случай, если админ уверен, что это не подбор пароля, а просто
  человек забыл раскладку.

Как это устроено:

1. Открой `http://localhost:3000/admin.html`, введи пароль.
2. После нескольких неверных попыток подряд — временная блокировка (как и
   при обычном входе), чтобы пароль нельзя было перебирать вслепую.
3. Все данные (аккаунты, галочки, бан, группы) хранятся так же в памяти
   сервера — при перезапуске сервера восстанавливаются из `data/store.json`
   вместе с остальным состоянием, как и раньше.
4. Админ-сокет полностью отделён (namespace `/admin`) от обычных чатов —
   у него нет доступа к сообщениям и паролям пользователей в открытом виде.

**Важно:** это по-прежнему демо-защита — общий набор паролей в памяти
сервера, без ролей и разграничения прав между админами. Журнал действий
теперь подписывает, кто (по имени из `ADMIN_ACCOUNTS`, если задан) и с
какого IP выполнил действие, но живёт только в памяти процесса — при
перезапуске сервера обнуляется. Для продакшена нужна отдельная система
админ-аккаунтов с собственными логинами, правами и постоянным журналом.

### E2E-протокол — что уже есть и что осталось (по сложности)

Уже реализовано: Double Ratchet, verified safety numbers, индикатор смены
ключа, шифрование стикеров/GIF, локальная PIN-блокировка хранилища.

Не реализовано в этой версии (каждое — самостоятельная задача, не «довесок»):

- **Своя копия сообщений («заметки себе»)** — отдельный ключ для
  расшифровки собственной истории после перезагрузки страницы.
- **Синхронизация ключей между устройствами** — сейчас identity-ключ
  привязан к браузеру; нужен протокол линковки (по типу QR-кода в
  WhatsApp Web), чтобы передать ключи на новое устройство того же аккаунта.
- **Полноценный X3DH с одноразовыми prekeys** — сейчас общий секрет
  чата строится напрямую на identity-ключах (см. комментарий в начале
  E2E-раздела `app.js`); с prekeys можно было бы писать первое
  сообщение офлайн-получателю с лучшей deniability.
- **E2E для групповых чатов** — нужен протокол вроде Sender Keys
  (каждый участник шифрует один раз, ключ раздаётся остальным по их
  приватным 1-на-1 каналам); сейчас группы, как и раньше, без шифрования.
- **Зашифрованный бэкап ratchet-состояния на сервере** — чтобы
  восстановить чат при потере локальных данных без полной потери
  истории; сложно совместить с настоящим E2E, обычно решается
  резервным ключом/PIN, как в Signal.
- **Аудит/формальная проверка протокола** — самописная крипта, даже
  правильно работающая на тестах, не то же самое, что аудированная
  библиотека (libsignal-client, matrix-org/olm). Перед реальным
  использованием стоит либо взять готовую библиотеку, либо прогнать
  эту реализацию через специалистов.
